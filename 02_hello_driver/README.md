# 02. Hello Driver (Символьное устройство)

Этот проект — первый полноценный драйвер символьного устройства (Character Device) для Linux.
В отличие от `01_hello_world`, этот модуль не просто пишет в лог, а создает виртуальный файл в системе, через который можно обмениваться данными.

## Что делает драйвер?

1. При загрузке модуля (`insmod`) он:
   - Выделяет уникальный номер устройства (`alloc_chrdev_region`).
   - Регистрирует символьное устройство (`cdev_add`).
   - Создает файл `/dev/my_hello`, который выглядит как обычный файл, но на самом деле является "дверью" в наш драйвер.
2. При попытке записать что-то в `/dev/my_hello` (например, через `echo`) вызывается функция `my_write`, которая сохраняет текст в буфер ядра.
3. При попытке прочитать из `/dev/my_hello` (через `cat`) вызывается функция `my_read`, которая отдает сохраненный текст обратно.
4. При выгрузке (`rmmod`) все созданные ресурсы корректно освобождаются.

## Архитектура и ключевые функции

- **`file_operations`** — структура, которая связывает системные вызовы (открытие, чтение, запись) с нашими функциями.
- **`copy_to_user` / `copy_from_user`** — специальные функции для безопасного копирования данных между "миром пользователя" и "миром ядра". Напрямую передавать указатели нельзя — это приведет к Kernel Panic.
- **`class_create` / `device_create`** — современный способ заставить систему (udev) автоматически создать файл в `/dev`, чтобы не делать это вручную через `mknod`.

## Как собрать и протестировать

**1. Сборка модуля:**
```bash
cd 02_hello_driver
make
sudo insmod hello.ko
ls -l /dev/my_hello
echo "Привет из пользовательского пространства!" | sudo tee /dev/my_hello
sudo cat /dev/my_hello
sudo dmesg | tail -5
sudo rmmod hello
sudo dmesg | tail -5
make clean
